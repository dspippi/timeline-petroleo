1. Visão geral

A Timeline do Petróleo é uma aplicação em Next.js 14 com React e TypeScript voltada à visualização de eventos históricos, corporativos, tecnológicos e geopolíticos relacionados ao petróleo. O núcleo da experiência é uma timeline horizontal com zoom, pan, agrupamento por região e país, e sincronização visual com um gráfico do preço do Brent.

O projeto também inclui uma área administrativa local para manutenção do conteúdo. Essa área salva diretamente em arquivos JSON do repositório e foi pensada para uso no computador de trabalho, não como CMS online permanente.

Ponto central do projeto: o site público lê dados versionados em arquivos do próprio repositório. Ou seja: editar a aplicação significa editar arquivos locais, validar e depois publicar via Git.

2. Estrutura do projeto

As pastas abaixo são as mais importantes para entender o funcionamento da aplicação.

Frontend público

  • app/page.tsx: página inicial com a timeline.
  • components/Timeline/: renderização da timeline, linhas, marcadores, tooltip e wrapper principal.
  • components/OilChart/: gráfico de preços do petróleo.
  • app/sources/page.tsx: página pública de fontes e referências.
  • context/ e hooks/: filtros, sincronização e preferências.

Dados e lógica

  • data/events.json: base principal de eventos.
  • data/categories.json: categorias, rótulos, cores e formatos.
  • data/sources.json: lista de referências exibidas em /sources.
  • data/oil-prices-*.json: base local de apoio para o gráfico.
  • lib/: leitura/escrita de dados, datas, categorias, escala e tema.

Admin e APIs

  • app/admin/: telas do painel administrativo.
  • app/api/admin/: endpoints para eventos, categorias, fontes, tema e editor bruto.
  • middleware.ts: trava ou libera o admin conforme o ambiente.

Ferramentas auxiliares

  • scripts/events-excel.mjs: interface CLI para Excel.
  • scripts/events-excel-core.cjs: regras de importação e exportação.
  • dist/: saída opcional do executável do editor Excel.
  • docs/: documentação e arquivos de apoio locais.
Importante: data/events.xlsx é um arquivo local de apoio. Ele não precisa ir para produção e está ignorado pelo Git.

3. Arquitetura de execução

O fluxo principal da home funciona assim:

app/page.tsx
  -> parseEvents() / listEvents()
  -> lê data/events.json no servidor
  -> converte datas para string (serialização)
  -> envia para TimelineClientWrapper
  -> wrapper reconstrói Date, aplica filtros e desenha a timeline

Camada server

app/page.tsx lê os eventos no servidor para que a página já nasça com dados prontos. O parser usado hoje é listEvents(), reexportado por lib/parseEvents.ts.

Camada client

TimelineClientWrapper recebe os eventos serializados, reconstrói as datas, cria escala temporal, controla filtros, sincroniza hover e monta a interface.

Camada API

app/api/oil-prices/route.ts alimenta o gráfico. app/api/admin/* faz as operações de edição local dos arquivos.

A aplicação usa app/layout.tsx para registrar três providers globais: CategoriesProvider, SettingsProvider e TimelineSyncProvider. Eles mantêm o estado compartilhado de categorias, preferências visuais e sincronização de hover/zoom.

4. Modelo de dados

O objeto central da aplicação é o evento da timeline.

Campo Obrigatório Formato Uso na aplicação
id Sim Texto único Identificador interno. É usado para edição, atualização e exclusão.
title Sim Texto Título visível do evento na tabela e no card.
start_date Sim YYYY-MM-DD Data inicial usada para ordenação e posicionamento.
end_date Não YYYY-MM-DD ou null Se existir, o evento vira intervalo. Se não existir, vira marcador pontual.
country Sim Texto Usado em agrupamentos, filtros e busca.
region Sim Texto Define o agrupamento principal da timeline.
type Sim ID de categoria Controla cor, rótulo e formato visual do evento.
company Não Texto ou null Empresa relacionada ao evento.
wikipedia Não URL ou null Link de referência dentro do card do evento.
description Não Texto Descrição longa exibida ao abrir o detalhe do evento.

Exemplo do formato persistido em data/events.json:

{
  "id": "drake-well-titusville-1859",
  "title": "Poço Drake: Início da Era do Petróleo",
  "start_date": "1859-08-27",
  "end_date": null,
  "country": "Estados Unidos",
  "region": "América do Norte",
  "type": "discovery",
  "company": "Seneca Oil Company",
  "wikipedia": "https://en.wikipedia.org/wiki/Drake_Well",
  "description": "Edwin Drake perfura o primeiro poço de petróleo..."
}
Regra prática: o tipo do evento precisa corresponder a um id existente em data/categories.json. Se você remover uma categoria ainda usada em eventos, o dado continua salvo, mas a interface pode perder o rótulo ou a cor esperada.

5. Como usar o site público

Timeline principal

  • Arraste com o mouse para mover a timeline horizontal e verticalmente.
  • Use Ctrl + scroll para aplicar zoom temporal.
  • Use os controles da interface para ampliar, reduzir, resetar ou ajustar a escala.
  • Passe o mouse para ver a data sincronizada entre timeline e gráfico.
  • Clique em um evento para abrir o card com título, descrição, país, empresa e link.

Filtros e configuração

  • Os filtros trabalham por país, tipo e empresa.
  • As preferências visuais incluem densidade, tamanho dos marcadores e modo escuro.
  • A timeline é agrupada por região e país, com distribuição em faixas para evitar sobreposição.

Gráfico do petróleo

  • O gráfico usa Recharts e a mesma escala temporal da timeline.
  • Ele lê dados via /api/oil-prices, com base local de fallback em JSON.
  • O hover é sincronizado com a timeline para facilitar leitura comparativa.

Página de fontes

  • /sources lista livros, sites, datasets e artigos cadastrados em data/sources.json.
  • Cada item pode exibir ano, tipo, autor, descrição, imagem e URL.

6. Área administrativa

A área administrativa fica em /admin. Em ambiente local de desenvolvimento ela é liberada automaticamente. Em produção, o middleware.ts a bloqueia por padrão e só a expõe se ALLOW_ADMIN_ONLINE=1 estiver configurado.

Recomendação do próprio projeto: trate o admin online como exceção. O fluxo confiável é editar localmente, revisar os arquivos modificados e publicar por Git.

Eventos

Tela principal do admin. Mostra contagem total, busca por título ou país, filtro por tipo, ordenação por colunas e ações de editar ou excluir.

Categorias

Permite criar e editar categorias em data/categories.json, com id, rótulo, cor hexadecimal e formato do marcador.

Fontes

Permite manter data/sources.json, que abastece a página pública de fontes.

Cores & Tema

Edita variáveis CSS de app/globals.css para os modos claro e escuro.

Editor de Texto

Abre o conteúdo bruto de data/events.json para edição manual com validação de JSON no salvamento.

Mapa de Plataformas

Há um atalho no topo do admin para a página /mapaplataformas, aberta em nova aba.

A persistência dos eventos é feita por lib/adminEvents.ts. As funções principais são listEvents(), addEvent(), updateEvent(), deleteEvent(), readRawEvents() e writeRawEvents().

7. Como adicionar eventos

O fluxo recomendado para cadastrar um evento novo é usar a tela /admin/events/new.

  1. Abra o projeto localmente com npm run admin ou npm run dev e acesse http://localhost:3000/admin.
  2. Clique em + Novo Evento. O formulário usa as categorias existentes e oferece sugestões de países e empresas já presentes na base.
  3. Preencha Título, Data de início, País, Região e Tipo. Esses são os campos mínimos para um cadastro consistente.
  4. Revise o ID. No modo de criação ele é gerado automaticamente a partir do título e do ano, mas pode ser editado manualmente. O ID precisa ser único.
  5. Se o evento for um período, preencha também Data de fim. Se for um fato pontual, deixe esse campo vazio.
  6. Preencha os campos opcionais Empresa, Wikipedia e Descrição quando fizer sentido.
  7. Salve. O endpoint /api/admin/events grava o conteúdo em data/events.json e reordena os eventos por start_date.

Regiões disponíveis hoje no formulário:

  • Global
  • América Central e do Sul
  • América do Norte
  • Oriente Médio
  • Europa
  • Ásia
  • África
  • Outros
Dica editorial: use títulos curtos e descrições mais completas. O título precisa funcionar bem na listagem; a descrição é o lugar para contexto histórico.

8. Como usar a planilha events.xlsx

O repositório inclui um fluxo formal para trabalhar com Excel. Ele existe para cenários em que editar dezenas de eventos em tabela é mais rápido do que usar o formulário do admin.

Comandos principais

npm run excel:export
npm run excel:import
npm run excel:ui

O que cada um faz

  • excel:export: gera ou atualiza data/events.xlsx a partir de data/events.json.
  • excel:import: lê data/events.xlsx e sobrescreve data/events.json.
  • excel:ui: abre um menu simples no terminal para escolher exportar ou importar.

As colunas esperadas pela ferramenta Excel são exatamente estas:

Coluna Obrigatória Observação
idSimPrecisa ser único.
titleSimTítulo do evento.
start_dateSimFormato textual esperado: YYYY-MM-DD.
end_dateNãoVazio vira null.
countryNão na importação, mas recomendadoNão é obrigatório no parser Excel, mas é obrigatório para um evento consistente na aplicação.
regionNão na importação, mas recomendadoDefine agrupamento visual.
typeNão na importação, mas recomendadoDeve corresponder a uma categoria válida.
companyNãoVazio vira null.
wikipediaNãoVazio vira null.
descriptionNãoTexto livre.

Fluxo recomendado com Excel:

  1. Execute npm run excel:export para garantir que a planilha reflita a versão atual do JSON.
  2. Abra data/events.xlsx no Excel e faça as alterações em lote.
  3. Não mude o nome das colunas. A importação exige os cabeçalhos corretos.
  4. Mantenha datas no padrão YYYY-MM-DD para evitar ambiguidade.
  5. Ao terminar, rode npm run excel:import.
  6. Confirme digitando IMPORTAR quando o script pedir confirmação.
  7. Revise o data/events.json gerado e abra o site local para conferir o efeito visual.
Segurança do fluxo: no import, a ferramenta cria automaticamente um backup do JSON atual em um arquivo do tipo data/events.json.bak-AAAAMMDD-HHMMSS antes de sobrescrever.

A importação ignora linhas sem id, title ou start_date. O script também reordena os eventos pela data inicial.

Se quiser distribuir a ferramenta Excel separadamente para uso local, o projeto também possui npm run excel:exe, que gera dist/events-excel.exe. Se o executável for aberto fora da raiz do projeto, passe a pasta manualmente com --root "C:\caminho\para\Timeline do Petróleo v2".

9. Manutenção de dados e personalização

Categorias

O editor de categorias salva a lista completa em data/categories.json. Cada categoria tem id, label, color e shape.

O endpoint de salvamento valida cor em formato #rrggbb, proíbe IDs duplicados e aceita apenas letras minúsculas, números, hífen e sublinhado no id.

Fontes

O editor de fontes salva tudo em data/sources.json. Os campos usados são: id, title, author, year, type, url, imageUrl e description.

Tema

O editor de tema altera variáveis CSS diretamente em app/globals.css, tanto para modo claro quanto escuro. Depois de salvar, recarregue a página para ver o resultado completo.

Editor de Texto

Use apenas quando precisar de controle total sobre o JSON. O salvamento passa por writeRawEvents(), então JSON inválido é rejeitado antes de gravar.

Quando usar cada ferramenta:

  • Use Admin para criar ou ajustar poucos eventos manualmente.
  • Use Excel para grandes lotes de edição.
  • Use Editor de Texto para correções estruturais, colagens controladas ou operações muito específicas.
  • Use Categorias quando surgir um novo tipo de evento ou quando quiser mudar cor/forma existentes.
  • Use Fontes para manter a página pública de referências coerente com o conteúdo.
  • Use Tema para ajustes visuais globais da aplicação.

10. Publicação e rotina de trabalho

O fluxo esperado de manutenção do conteúdo é local, versionado e revisável.

  1. Edite os dados pelo admin, Excel ou editor bruto.
  2. Revise os arquivos alterados, principalmente data/events.json, data/categories.json e data/sources.json.
  3. Abra o site localmente para validar se a timeline, os filtros e o gráfico continuam corretos.
  4. Faça o commit apenas dos arquivos que realmente devem ir para o repositório.
  5. Envie com git push. O deploy do Vercel publica a nova versão do site.

Comandos usuais:

git status
git add data/events.json data/categories.json data/sources.json app/globals.css README.md docs/manual-de-uso.html
git commit -m "Atualiza conteúdo e documentação"
git push
Arquivos locais que normalmente não devem ser publicados: data/events.xlsx, backups data/*.bak-*, dist/ e artefatos temporários.
